# Мониторинг проверки M1

`dashboard.json` — панель для Prometheus-источника в Grafana. При импорте выбрать
источник метрик своего стека. Окружения `dev` и `pilot` выбираются отдельно.
Панель показывает результат, возраст данных и длительность проверки.
Папка имеет UID `zont-m1`, панель — `zont-m1-overview`. Эти идентификаторы должны
различаться: при совпадении интерфейс списка Grafana может зациклиться при обходе
дочерних объектов и показать ошибку `too much recursion`.

Для повторяемой настройки использовать `infra/scripts/grafana_setup.py` в Docker
с образом `zont-m1-tools:local`. Смонтировать `infra/` только для чтения и передать
путь к отдельно смонтированному приватному JSON. Обязательные поля конфигурации:
`stack_url` и `service_account_token`; необязательные — `datasource_uid` и
`contact_point` (имя уже существующего канала). По умолчанию выбирается единственный
основной Prometheus-источник. Пример команды внутри контейнера:
`python /infra/scripts/grafana_setup.py /private/grafana-access.json`.

Сценарий создаёт либо обновляет только папку и объекты M1, проверяя их принадлежность
проекту. Общие политики и каналы уведомлений не меняются. Каждый запуск оставляет
правило приостановленным: включение выполняется отдельно после проверки данных
и доставки. Повторный запуск настройки активного мониторинга приостановит правило.

Runtime отправляет два измерения через OTLP: `zont_m1_probe_success` (0 или 1)
и `zont_m1_probe_duration_seconds`. Это результат инфраструктурной проверки,
а не показатель здоровья приложения. Проверка запускается раз в час.

Доступ хранится в ключе Lockbox `grafana_otlp_config`: JSON с полями `endpoint`,
`username` и `token`. `username` — идентификатор OTLP instance. В заголовке
`Authorization: Basic …` пара `username:token` закодирована Base64; это секрет,
а не шифрование. Значения не помещаются в Terraform или исходный код.
Runtime подключает ключ при `grafana_metrics_enabled=true`.

`alert-rule.json` — шаблон запроса API provisioning Grafana. Перед загрузкой
заменить `${datasource_uid}`, проверить `orgId` и создать папку `zont-m1`.
Правило для `dev` изначально приостановлено. Оно выявляет последний отказ либо
отсутствие измерений за два часа; условие должно сохраняться пять минут.
Ошибка запроса к источнику тоже считается отказом.

До включения правила выбрать канал владельца и проверить доставку. Не заменять
общую политику уведомлений стека: использовать отдельную маршрутизацию проекта
или канал в настройках правила. При штатном выключении расписания приостановить
правило, иначе отсутствие данных вызовет ожидаемый алерт.

Готовность требует отдельной проверки: реальный вызов контейнера → измерение
в источнике → отказ/восстановление правила → уведомление владельцу. Импорт панели
и успешная авторизация OTLP сами по себе эту проверку не заменяют.
