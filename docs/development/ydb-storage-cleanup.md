# Очистка накопленных снимков и графиков YDB

`#for-human`

Задача [#99](https://github.com/tupoybot/ZontAnalyzer/issues/99) применяет
[правила хранения #57](./ydb-storage-growth.md) к накопленным данным.
Она меняет только `config_snapshots` и проверенные ключи графиков `chart-data:v2`
в `app_meta`. Исходная телеметрия, события, отчёты, AI, пользовательские записи
и история газовых пересчётов сохраняются. Приложение продолжает работать;
изменений его кода и схемы таблиц для операции не требуется.

## Что сохраняется

Для настроек остаётся первое наблюдение каждого последовательного изменения,
его исходные `id` и `captured_at`. Возвращение A → B → A сохраняется отдельным
событием. Меняющиеся показания убираются только из прежних полных снимков;
полное последнее состояние устройства остаётся в `devices`.

Для графика сначала проверяется пакет, соответствующий текущему отчёту.
Действующий пакет `v3` имеет приоритет; иначе используется подходящий `v2`.
Данные графика переносятся без пересчёта и обращения к телеметрии или AI.
Старые версии удаляются только после проверки сохранённой замены. Если
актуального пакета или самого отчёта нет, его старые ключи остаются и попадают
в отдельный счётчик необработанных строк.

## Защита операции

`tools/cleanup_ydb_storage.py` работает с приватной выгрузкой пяти таблиц:
снимков, отчётов, служебных значений, устройств и последовательностей номеров.
Каждая таблица читается как отдельный снимок; это не единый снимок всей БД.
Файлы содержат исходные данные, поэтому создаются вне репозитория, с правами
`0600` в новом каталоге `0700`. Неполная выгрузка не получает манифест готовности.

План фиксирует точные исходные строки и их замены. Перед применением утилита
проверяет контрольные суммы выгрузки и плана, пересоздаёт план из исходных данных
и сверяет отпечаток адреса БД и пространства таблиц с текущим подключением.
Проверка не позволяет случайно применить план к другой базе.

Настройки обрабатываются транзакциями до 50 исходных строк и 2 МиБ их полезной
нагрузки. Для графика одна транзакция обрабатывает один отчёт, не более 128 старых
ключей и 8 МиБ данных. Внутри транзакции повторно сравниваются исходные байты;
пакет графика дополнительно защищён сравнением актуального отчёта.
Изменившаяся строка не удаляется. Конфликт снимка останавливает операцию;
конфликт графика оставляет этот отчёт необработанным. Код завершения — `2`.

Уже завершённые порции сохраняются при остановке. Повторное применение того же
плана допускает отсутствующие исходные строки только при наличии точной замены.
Новые строки, которых нет в плане, не удаляются. Во время частичного прохода
история настроек может временно содержать обе формы записи одного наблюдения.

## Порядок выполнения

Все команды Python запускаются в локальном Docker-контейнере с исходниками
только для чтения и отдельным приватным каталогом. Настройки подключения YDB
передаются приватно; учётные данные и содержимое выгрузки в Git не помещаются.

1. Убедиться, что работает версия приложения с правилами #57. Получить свежую
   резервную копию YDB и дождаться `READY`, сверив БД и пространство таблиц.
2. Создать выгрузку и план. Проверить объём удаления, оставляемые данные,
   ограничения транзакций и отпечаток плана.
3. Восстановить выгрузку на изолированной локальной YDB, сверить исходные байты,
   выполнить очистку, повторный запуск и возврат исходных таблиц. Проверить
   историю настроек, отчёты, AI и HTML четырёх видов отчётов.
4. Применить проверенный план к рабочей базе, получить новую выгрузку и сравнить
   её с исходной. Параллельные изменения учитываются явно; неполная обработка
   не считается успехом. Проверить готовность и авторизацию приложения.

```sh
python -m tools.cleanup_ydb_storage export /private/before
python -m tools.cleanup_ydb_storage plan /private/before
python -m tools.cleanup_ydb_storage apply /private/before --plan-sha256 REVIEWED_SHA256
python -m tools.cleanup_ydb_storage export /private/after
python -m tools.cleanup_ydb_storage verify /private/before /private/after
```

Для восстановления сохраняются исходная выгрузка, манифест, проверенный план
и резервная копия. Проверка возврата затронутых таблиц на локальном стенде не
заменяет полное восстановление облачной резервной копии из #79. Рабочие таблицы
при восстановлении нельзя очищать целиком: новые записи вне плана должны сохраниться.

Размер полезной нагрузки и физическая статистика YDB измеряются отдельно.
Физическое место освобождается по мере обработки удалений и обновления статистики;
немедленное уменьшение файла выгрузки не доказывает такое же уменьшение рабочего
хранилища. Разовые RU очистки не являются оценкой дальнейшей экономии RU.
