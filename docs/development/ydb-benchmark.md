# Локальный стенд измерения ресурсов YDB

`#for-human`

Задача [#70](https://github.com/tupoybot/ZontAnalyzer/issues/70) добавляет
воспроизводимое сравнение двух версий приложения в Docker: синтетическая история,
наблюдение обращений к базе, JSON/CSV и локальная Grafana с Prometheus.
Рабочая база, ZONT, OpenAI и облачная публикация не используются.
Расходы локальной YDB не являются расчётом счёта облачного провайдера.
RU — условная единица ресурсов, затраченных сервером на запрос.

## Запуск и результат

Из корня репозитория, с пустым каталогом результатов вне репозитория:

```sh
deploy/measure-ydb-lab.sh run /absolute/path/to/empty-results BASELINE_SHA
deploy/measure-ydb-lab.sh stop /absolute/path/to/empty-results
```

`BASELINE_SHA` — принятый коммит для сравнения; без аргумента используется `HEAD`.
Первая версия загружается из его `src`, вторая — из текущего рабочего дерева.
Сценарии и измеритель одинаковы для обеих версий. По умолчанию выполняются
**три повтора для 1, 5 и 10 лет**, отдельно прикладной и газовый наборы.
Частичный запуск, например `ZONT_LAB_YEARS=1 ZONT_LAB_REPEATS=1`,
проверяет выбранные сценарии, но не удовлетворяет требованию полной матрицы.

Готовность базы проверяется через создание, запись, чтение и удаление
пробной таблицы. Для каждой версии установлен предел 1800 секунд;
`ZONT_LAB_RUN_TIMEOUT_SECONDS` меняет его. При ошибке сохраняются ограниченные
диагностические данные, затем удаляются ресурсы этого запуска. При успехе
панель остаётся доступной по адресам из `local-urls.txt` только через локальный
интерфейс. Команда `stop` удаляет контейнеры, сети и том Prometheus своего
стенда, сохраняя файлы результатов.

| Файл | Содержание |
| --- | --- |
| `results.jsonl` | Наблюдавшиеся попытки RPC — отдельных обращений клиентской библиотеки (SDK) к серверу; операции, проверки фактов и расходы сборщика |
| `measurements.jsonl` | Компактные сводки и окна без повторного хранения RPC; источник данных панели |
| `summary.json` | Медиана, минимум и максимум повторов; полнота измерений, совпадение результатов, суммарные расходы |
| `operations.csv`, `windows.csv` | Показатели операций и окна RU/с для самостоятельного анализа |
| `summary-gate.json`, `run-selection.txt` | Проверенный объём запуска и его технический итог |
| `images.lock`, `dependencies.json`, `machine.txt`, `storage-mode.json` | Образы, SDK, параметры машины и подтверждённый режим дисков |
| `lab-image.tar.gz` | Сохранённый тестовый образ для восстановления через `docker load -i` |
| `source-sha256.txt`, `candidate.patch`, файлы `*-sha.txt` | Исходные версии и изменения рабочего дерева |
| `candidate-source/` | Снимок исходников, сценариев и конфигурации, используемый в запуске |
| `*-facts.json` | Синтетические факты, артефакты публикации и сохранённые AI-ответы |

Каталог закрыт правами `0700`. Даже синтетический запуск сохраняет сведения
о локальной среде и рабочую разницу Git: перед публикацией нужно отобрать
и проверить конкретные файлы. Автоматической отправки результатов нет.

## Изоляция и повторяемость

Для образа YDB задан неизменяемый идентификатор содержимого — digest —
в [скрипте запуска](../../deploy/measure-ydb-lab.sh).
Версии Prometheus и Grafana разрешаются в digest перед запуском и сохраняются
в `images.lock`; тестовый образ собирается из снимка, сохраняется в архив
и запускается по неизменяемому ID. Снимок исходников
содержит отслеживаемые и новые неигнорируемые файлы выбранных каталогов;
он монтируется только для чтения. Внутренняя сеть базы и исполнителя не имеет
внешнего выхода. Дополнительная сеть панелей нужна для доступа с хоста;
трансляция исходящих адресов в ней отключена.

Каждый повтор создаёт чистое пространство таблиц и каталог публикации;
после сценария таблицы удаляются. Фиксированы входные данные, порядок операций,
время отчётов и идентификаторы синтетических показаний. Часы SDK и механизм
блокировок работают обычно. Контрольные `cold/warm` означают первый запрос
и его повтор в новом пространстве: все кэши сервера принудительно не очищаются.
Подготовка и проверочные чтения учитываются отдельно от полезной работы.

Переиспользованы принятые сценарии
[`benchmark_operations_cost.py`](../../tools/benchmark_operations_cost.py) и
[`benchmark_gas_updates.py`](../../tools/benchmark_gas_updates.py).
Длинная история разрежена: три точки в сутки; в газовом наборе дополнительно
32 дня с шагом десять минут. Газовый архив содержит 15/63/123 отчёта.
Это проверка зависимости затрат от истории, а не нагрузочная модель полного
ежедневного архива за десять лет.

Факты, HTML/JSON и сохранённые AI-ответы должны совпадать у обеих версий
и во всех повторах одного набора. Исключено только время изменения файла
`published_at` в файловом указателе `reports.json`. Настройки, входные версии,
содержание отчётов и AI-текст не нормализуются. Несовпадение прерывает проверку.

## Источник и полнота расходов

`measured_ru` берётся из серверного
[`x-ydb-consumed-units`](https://ydb.tech/docs/en/reference/ydb-sdk/grpc-headers).
Заголовки начала и конца одного потока не складываются дважды. Повтор SDK
учитывается отдельной попыткой; управление транзакциями и потоковое чтение
также наблюдаются. Известные операции управления схемой и сессиями отмечены
отдельно. Неизвестный метод, незавершённое обращение и неподдерживаемый путь
SDK не считаются полным измерением.

Для Query API запрашивается `BASIC`: агрегированная статистика без плана запроса.
Подготовка данных оставляет штатный режим SDK. Поля CPU компиляции, координации,
фаз и общего времени CPU, строки и байты сохраняются отдельно, если сервер
их предоставил. Пропущенное поле остаётся неизвестным. Оценка `estimated_ru`
по [правилам YQL](https://yandex.cloud/ru/docs/ydb/pricing/ru-yql) допускается
только при наличии всех нужных составляющих CPU и ввода-вывода; она не подменяет
серверные RU. Формула YQL не применяется к `ReadTable`.

У закреплённой версии сервера есть подтверждённые ограничения:

- Ошибочный `ExecuteQuery` не получает RU: сервер устанавливает заголовок
  [только при успешном ответе](https://github.com/ydb-platform/ydb/blob/1bd0f9c372384549fe4ff21c29f44609a20f5450/ydb/core/grpc_services/query/rpc_execute_query.cpp#L453-L455).
- `ReadTable` вычисляет внутренний расход, но
  [не возвращает его заголовком](https://github.com/ydb-platform/ydb/blob/1bd0f9c372384549fe4ff21c29f44609a20f5450/ydb/core/grpc_services/rpc_read_table.cpp#L634-L671).
- Статистика CPU и ввода-вывода доступна не для каждого метода и поля.

Полный расход таких сценариев остаётся `null`. Рядом выводятся причины,
покрытие и `partial_known_ru_total` — **только известная часть**, которую нельзя
называть полным расходом. `accounting_complete=false` сохраняется даже при
успешной технической проверке `validation_passed=true`. Последняя проверяет
матрицу, повторяемость, совпадение фактов и измерение накладных расходов;
она не означает приёмку владельцем или полноту RU.

## Время, окна и панель

RU/с — сумма RU завершившихся обращений, делённая на длительность окна.
Сохраняются окна 1 и 60 секунд, включая пустые; последний неполный отрезок
использует свою фактическую длительность. Долгий запрос учитывается при
завершении: пик не описывает распределение затрат внутри запроса.
Неизвестный расход делает соответствующее окно неполным.
Среднее считается как сумма RU, делённая на общее наблюдавшееся время;
короткий последний отрезок не получает вес целого окна. При неизвестном расходе
хотя бы одного окна полные максимум и среднее RU/с не публикуются.

Панель показывает медианы операций, максимум и среднее RU/с последнего
завершённого повтора, полноту, CPU, чтения, записи, ошибки и доступные сведения
об очереди. Показатели обновляются после завершения сценария; точные границы
окон находятся в CSV. Метки ограничены названиями сценариев, версией,
набором и длиной истории; SQL, параметры и идентификаторы в метрики не попадают.
Частота обращений RPC показывается отдельно от RU/с. Возраст очереди отсчитывается
по монотонным часам клиента с подтверждения записи элемента в очередь.
Так он не зависит от фиксированной даты отчётов. Для уже существовавшего
непрослеженного элемента или несовпавшего числа элементов возраст неизвестен.
Старые измерения без отметки `queue_age_clock=monotonic` не дают возраст
непустой очереди; после опустошения возраст равен нулю.

Цена измерителя сравнивается на пяти одинаковых контрольных чтениях с ним
и без него: отдельно время и CPU клиентского процесса. Измеряемый интервал
включает запрос статистики, её обработку, вычисление хешей и запись результатов.
Таким образом учитываются накладные расходы всего сбора измерений. Пять чтений без
наблюдения намеренно исключены из учёта RPC и отмечены в результате.
Холостой наблюдатель измеряется отдельно. Расходы подготовки, проверок,
наблюдателя и основных операций не смешиваются в итоговой сумме сценария.

## Покрытые сценарии

| Набор | Что проверяется |
| --- | --- |
| Контроль | Чтение, запись, CPU-запрос, транзакция, `ReadTable`, границы телеметрии |
| Пустые вызовы | Планировщик, обслуживание, мониторинг |
| Сбор | Новый сбор, повтор, новая и поздняя точка; повтор не меняет версию источника |
| Отчёты | Готовый отчёт, день/месяц/сезон, публикация и её возобновление |
| Газ | Новое и исправленное показание, повтор модели, поздняя модуляция, завершение очереди публикации |
| Сбои | Ошибка запроса и восстановление, повтор транзакции, потеря блокировки после сохранения отчёта и продолжение без повторного анализа |

Рабочее облачное приложение этот стенд не меняет. Перед выводом об экономии
облака нужны сопоставимые наблюдения управляемой облачной YDB; локальные RU и CPU не являются
доказательством оплаты. Полезная работа, факты и сохранённые ответы должны
сохраняться при любом последующем снижении затрат.
