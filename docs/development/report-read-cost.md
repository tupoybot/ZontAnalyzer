# Стоимость чтения отчётов и повторного расчёта

`#for-human`

Контракт [#64](https://github.com/tupoybot/ZontAnalyzer/issues/64): сохранять
содержимое отчётов, AI и порядок публикации, сокращая повторные чтения и расчёты.

## Что изменено

Семь предыдущих дневных отчётов выбираются по небольшому синхронному индексу
`reports.by_kind_end` (`kind`, `period_end`). Сначала читаются ключи, затем только
выбранное содержимое. При одинаковом конце периода сохраняется прежний порядок
по `id`: пограничная группа обрабатывается страницами, в памяти остаются семь
лучших кандидатов. Стоимость такой группы зависит от числа одинаковых периодов,
а не от остального архива.

Последний завершённый день ищется обратным проходом по первичному ключу.
Незавершённые отчёты и будущие концы периода пропускаются. Курсор содержит все
поля ключа, поэтому версии одного периода не теряются между страницами.

Индекс добавляется идемпотентно при инициализации. Для рабочей базы его следует
подготовить вызовом `ensure_read_indexes` до смены образа и дождаться `READY`.
Это дополнительная структура чтения: состав таблиц, исходные записи и базовый
хеш схемы v2 сохраняются. Прежний образ совместим с индексом, а старые экземпляры
приложения продолжают атомарно обновлять его средствами YDB. Копирование базы
принимает исходную схему и эту известную дополнительную структуру; неизвестные
индексы по-прежнему требуют явного решения.

Внутри проверки одного периода старый отчёт и отпечаток событий читаются один
раз и используются при проверке прежних форматов подписи. Проверки под блокировкой
и обнаружение поздних событий сохраняются. Расчёт без AI больше не читает старый
отчёт, который ему не нужен.

Газовая модель восстанавливается из сохранённого снимка после проверки полного
прежнего ключа входов. Типы, версии и состав снимка проверяются; повреждённый
снимок пересчитывается. Смена входов во время расчёта отвергается. Параметры,
интервалы, неопределённость, версия модели и полный контекст отчёта сохраняются.
Повторное построение интервалов и правила обновления архива относятся к #58.

## Парные измерения

Команда для одноразовой локальной YDB:

```sh
deploy/check-local.sh build
deploy/measure-ydb-cost.sh /absolute/private/artifacts 273dfca
```

Переменная `ZONT_COST_CASES` позволяет выбрать `reports`, `queue` или `gas`.
Исходники монтируются только для чтения; стенд удаляет собственные контейнеры
и сеть. Артефакты содержат точные исходники сравнения, их хеши и идентификаторы
образов. При сравнении отчётов исходный вариант запускается без нового индекса:
оптимизатор YDB может выбрать его даже для неизменённого старого SQL.

Статистика RPC учитывает все наблюдавшиеся попытки запросов и завершения
транзакций. RU берутся из заголовка сервера, строки и байты — из полной
статистики. Отсутствующие показатели отмечаются явно. Это серверные RU локальной
YDB, а не тарификация managed YDB и не денежная экономия.

| История | Семь предыдущих, RU до → после | Последний завершённый день, RU до → после |
| --- | ---: | ---: |
| 1 год | 365 → 36 | 365 → 18 |
| 5 лет | 1825 → 36 | 1825 → 18 |
| 10 лет | 3650 → 36 | 3650 → 18 |

Здесь исходный код — `3149665`, включающий прежний полный обход отчётов.
Промежуточный `273dfca` уже уменьшал объём содержимого, однако чтение семи
предыдущих всё ещё требовало 379/1839/3664 RU. Новый индекс устраняет этот обход.
Для поиска одного периода сохраняется прежняя оптимизация: 14/12/13 RU на
этом прогоне вместо 365/1825/3650. Различия нескольких RU между прогонами могут
включать компиляцию запроса.

Цена индекса измерена отдельно на вставке синтетического отчёта: число записанных
строк увеличилось с двух до трёх, байты — с 2764 до 2791. В прогретых запросах
локальный сервер сообщил по 1 RU с индексом и без него; это не основание считать
индекс бесплатным в облаке. Содержимое отчёта в индекс не копируется.

Существующая пакетная очередь сохраняет выбор тех же восьми элементов:
чтение при 1/5/10 годах — 368/1826/3651 → 64/208/391 RU. Число ожидающих элементов
в этом сценарии растёт вместе с архивом; этот результат не обещает постоянной
стоимости подсчёта непустой очереди. Газовый прогон пока подтверждает равенство
результатов после перезапуска, но продолжает читать дневные агрегаты всей
калибровки; следующее изменение должно устранить этот повтор.
