## Метод измерения

Сначала измеряется существующий полный набор тестов без изменения фикстур,
числа процессов и ресурсов. Actions сохраняет тестовый Docker-образ; локальный
прогон загружает именно этот образ и использует тот же commit, тестовые данные
и `deploy/check-local.sh check-prebuilt`. Исходники монтируются только для чтения.
Внешние API и production для измерений не используются.

Измерения разделяют подготовку окружения, готовность временной YDB, pytest и
проверку установленного CLI. Для каждого теста сохраняется время подготовки,
выполнения и очистки. Отдельно учитываются ограничения CPU/RAM и потребление
контейнеров. Длительность заданий Actions и ожидание от создания запуска до
последнего обязательного результата берутся из API GitHub; сумма времени
заданий показывает затраты runner, а не только длительность pytest.

## Условия завершения

- Повторные полные прогоны локально и в Actions позволяют сравнить результат
  до и после при совпадающих входных данных внутри каждой пары.
- Запросы, транзакции и хранение продолжают проверяться на настоящей YDB.
  Повторное использование схемы допускается только с проверенной очисткой
  данных и отдельными пространствами параллельных процессов.
- Чистая логика проверяется без зависимости от базы. Число процессов и лимиты
  выбираются по измерениям, все обязательные проверки остаются.
- Аудит охватывает все workflows, включая происхождение образа и порядок
  развёртывания. PR публикуется для принятия владельцем; до принятия merge запрещён.

## Изменения и проверяемые условия

В исходном стенде `YDB_USE_IN_MEMORY_PDISKS=1` не включала диски в памяти:
конфигурация запущенного сервера указывала файловый PDisk. Закреплённый образ
распознаёт значение `true`. Это соответствует проверке в
[исходном коде YDB](https://github.com/ydb-platform/ydb/blob/main/ydb/tests/library/harness/kikimr_config.py).
Теперь тестовый стенд проверяет фактические пути всех PDisks: они должны
использовать `SectorMap`. Несовпадение останавливает проверку до запуска тестов.
YDB остаётся настоящей: запросы, транзакции, индексы и хранение проверяет её
движок. Этот режим не является проверкой сохранности после потери питания.

Тесты с базой отмечаются `pytest.mark.ydb`; остальные выполняются в контейнере
без сети и без адреса YDB. Вызов общей фабрики базы из немаркированного теста
завершается ошибкой. Полный запуск всегда выполняет обе группы.

Каждый процесс получает собственные пространства таблиц. Внутри одного теста
несколько баз остаются раздельными; повторное создание runtime для одного
каталога сохраняет прежнее совместное использование базы. Между тестами
создаются новые клиенты и соединения. После завершения фоновых заданий
удаляются строки всех таблиц и восстанавливаются только две служебные записи
версии схемы. Ошибка очистки запрещает повторное использование пространства
и отражается в результате тестов. Тесты изменения схемы получают свежие таблицы.
В конце процесса удаляются все созданные пространства.

Отдельный локальный эксперимент `4a711d4` изменил режим дисков, сохранив прежний
образ, 849 Python-тестов, создание схем для каждого теста и один процесс.
Все тесты прошли без пропусков: pytest занял **723,314 с** вместо 3216,534 с.
Фазы setup/call/teardown — 61,923 / 460,355 / 195,995 с. Весь измеряемый цикл —
731,132 с. Максимальный наблюдённый счётчик записи YDB составил 17,1 MB,
память — 1,68 GiB. В исходном прогоне уже промежуточный снимок показывал
2,595 GB записи; полного конечного счётчика нет, точное отношение объёмов
поэтому не вычисляется. Проверка фактической конфигурации подтвердила `SectorMap`.

## Аудит workflows

| Workflow | Принятое изменение или сохранённая гарантия |
|---|---|
| `ci.yml` | Все прежние проверки сохранены. PR проверяет объединение с `main`; выпуск вызывает тот же набор на своём commit. Устаревшие PR-запуски отменяются. Образ для повторения выгружается только у PR с меткой `ci-benchmark`. |
| `application-release.yml` | Публикация зависит от успешного общего CI и получает готовый образ из того же запуска, с проверкой контрольной суммы. Повторная сборка и повторный Python-прогон удалены. Проверка допустимой ветки и её базы, commit в метках образа, smoke, неизменяемый digest и артефакт происхождения сохраняются. Выпуск по конкретному SHA не отменяется новым commit. |
| `infrastructure-check.yml` | Изменения workflow выпуска и деплоя также запускают проверки. Для обычной рабочей ветки устранена пара одинаковых запусков push/PR; отменяются устаревшие проверки PR. Ручной запуск сохранён. |
| `infrastructure-deploy.yml` | Порядок из PR #31 сохраняется: сначала подходящий проверенный образ, затем план и применение. Защищённые применения выполняются последовательно без отмены предыдущего. |
| `codex-bug-autofix.yml` | Сохранены ограничение по автору и метке issue, ручной запуск, последовательная обработка одной задачи и защита от повторной отправки. Причины менять этот workflow в измерениях не обнаружены. |

Фильтры выпуска и правила выбора образа используют одинаковый список входных
файлов. В него включены новые проверочные скрипты и остальные конфигурации,
которые читает общий CI. Контракт проверяется тестами маршрутизации и зависимостей.

Новый production-образ собирается и проходит smoke на runner общего CI,
используя тот же слой пакета, что и тестовый образ. Задание публикации получает
архив из своего запуска, проверяет SHA256, загружает образ и проверяет его
метки и работу перед отправкой в реестр. Оно не пересобирает зависимости.
Если неизменяемый тег этого SHA уже существует, сохраняется прежний порядок:
загрузка существующего образа, проверка меток и smoke без перезаписи тега.
В этом случае проверяются именно сохранённые байты ранее выпущенного образа.
Проверки ограничены 20 минутами, задание публикации — 15 минутами; превышение
срока завершает проверку ошибкой, а не пропуском тестов.
