# Оценка этапа 6

`tests/fixtures/reasoning/stage6_cases.json` содержит десять синтетических
пакетов с ожидаемыми структурированными ответами. Пакеты используют тот же
контракт, что и `analysis_packet`: качество, метрики, события и bounded
`control_context`. Для каждого кейса отдельно указаны обязательные поля
контекста и идентификаторы свидетельств, которые ответ должен иметь возможность
сослать.

Набор покрывает:

- успешный ручной эксперимент с сопоставимыми before/after периодами;
- неудачный эксперимент с rollback и ограниченным периодом наблюдения;
- обновление прошивки, откат и неполную историческую запись;
- ложное улучшение A/B при изменившихся погоде, режиме, ГВС и покрытии;
- сравнение autumn↔spring, autumn↔last autumn, winter↔shoulder и отсутствие
  предыдущего сезона;
- occupancy-гипотезу по нескольким косвенным сигналам;
- отсутствие прямой occupancy-гипотезы при явном контексте владельца.

`tests/unit/test_stage6_evaluation.py` проверяет, что все packets проходят
валидацию DTO и bounded packet contract, обязательный контекст сохраняет
`epistemic_level=context`, truncation не скрывает нужные поля, а expected mock
outputs проходят strict structured schema. Ссылки на evidence проверяются по
идентификаторам, реально присутствующим в packet; ответы с требуемой
неопределённостью должны содержать `unknowns`. Это проверяет наблюдаемую
структуру и трассируемость оценки, а не поиск отдельных строк в summary.

Набор и mock outputs не являются прогоном внешней модели и не доказывают её
содержательную точность. Они проверяют prompt/contract regression и пригодность
входа для последующей оценки. Реальная полезность на истории дома, выбор
владельцем допустимых экспериментов и окончательная owner acceptance остаются
открытыми до отдельной проверки владельцем.

Один разрешённый реальный запрос этапа 6 выявил starvation в weekly packet:
приоритетные `house_context`, `reliability`, `sensors` и legacy metrics могли
вытесняться длинными temporal windows/exclusion history и feedback. Allocator
получил отдельные bounded budgets для повторяющихся temporal списков, приоритет
для derived house/reliability/experiment context и сохранение representative
DHW/reliability events. Исправление проверено детерминированным replay исходного
weekly report локально; повторный внешний AI-запрос не выполнялся.
