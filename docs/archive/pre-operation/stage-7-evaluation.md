# Оценка этапа 7

## Воспроизводимые проверки без внешнего AI

`tests/fixtures/reasoning/stage7_cases.json` содержит десять пакетов, ожидаемые
структурированные mock-ответы и критерии ручной проверки:

| Сценарий | Что проверяется |
| --- | --- |
| Постоянная ошибка при разной погоде | Наклон не следует из постоянного смещения |
| Ошибка зависит от погоды | Наклон допустим как гипотеза с альтернативами |
| Дневной перегрев без CH | Внешние/внутренние теплопритоки и накопленное тепло |
| Узкий диапазон погоды | Недостаток данных для точной настройки |
| Жильцы просят теплее | Один доступный шаг уставки с проверкой комфорта |
| Владелец сообщил об отъезде | Экономичный режим может сохраняться |
| Присутствие неизвестно | Условный совет, не обязательное включение отопления |
| Утренний перелёт | PID не становится безусловной причиной |
| Порог автоматического лета | Направление, альтернативы, гистерезис и задержки |
| Контрфактуальный вопрос о ПЗА | Прогноз, допущения, уверенность и проверка |

Это проверки прохождения контракта и ручная рубрика, **не** десять выполненных
внешних AI-оценок. Общий лимит реальных запросов в этой итерации — один.

Отдельные детерминированные тесты проверяют диапазон погоды, различные уставки,
изменение режима внутри окна, нулевой mode/weather, неизвестный CH, плохое
покрытие, исключения, NaN, дубликаты и ограничение размера; восход у экватора,
местную дату у линии перемены дат и полярные условия. Сквозные тесты проверяют
передачу вопроса в AI, canonical/HTML/text, экранирование, сохранение старого
отчёта, обработку HTTP и сохранение компактных окон до урезания общего пакета.

## Реальная проверка

Для единственного контролируемого вызова используется неделя 31 августа —
7 сентября 2026 (Europe/Samara) на изолированной online-копии production.
Вопрос касается небольшого изменения ПЗА и уместности изменения порога лета;
разрешён максимум один ручной эксперимент. Проверяются обоснованная неизвестность
семантики настройки, альтернативы теплопритоков, отсутствие шаблона 20 → 22,
явный прогноз и отсутствие выдуманной точности. Результат и ограничения
фиксируются в [приёмке](stage-7-acceptance.md).

Реальный ответ выявил ошибку «один пример = все события». Счётчики полного журнала
добавлены в пакет и покрыты регрессией; внешнего повторного запроса нет. Ошибочная
часть проверяемого отчёта исправлена по canonical событиям с записью происхождения
редакции. Условные прогнозы и исходный API-ответ сохранены отдельно.
