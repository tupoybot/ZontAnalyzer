# Приёмка этапа 1.7

Ветка: `stage-7.1`. Аналитические эпохи и прежние пункты 9–11 исключены по решению владельца.
Именованных границ истории, отдельной ретроспективной команды и изменений уникальности отчётов нет.

## Реализовано

- Автоматический `new → ignored` через 48 часов, при startup и каждом цикле worker.
  Повторный maintenance идемпотентен; явные поздние `applied`/`rejected` сохраняются.
- Нейтральное «Без реакции» в HTML, `ignored` в CLI; AI feedback содержит только явные исходы.
- Миграционный checkpoint `9f4a2c8d1e70` без DDL: существующая БД получает проверенный online backup
  до первого массового изменения. До expiry выводится число затрагиваемых записей.
- Локальные тексты и AI-инструкция очищены от шаблонных сервисных советов; нормальный день может
  не содержать рекомендаций. Сохранённая AI-интерпретация старой политики не возвращается при refresh.
- Bootstrap запрашивает доступный архив по каждому устройству/типу, хранит завершённые части и
  фактические границы/`time_truncated`. `mintime=0` — граница протокола, не дата ремонта дома.
- CI проверяет push/PR; публикация GHCR только по `release-*` или ручному `publish=true`.
  Серверный Compose не содержит `build`; явный `release.sh` использует digest, backup и healthcheck.
  Локальная сборка и отладка имеют отдельный Compose и volume.
