# Задачи проекта в Codex Cloud

Codex Cloud запускает задачу в отдельном контейнере, берёт выбранную ветку
репозитория и выполняет сценарий подготовки окружения. Сценарий может повторно
запускаться при обновлении сохранённого контейнера. [Порядок работы Codex Cloud](https://developers.openai.com/codex/cloud/environments).

## Создание окружения

В настройках Codex Cloud создайте окружение для этого репозитория. Выберите
Python 3.12 и Node.js 22. В поля **Setup script** и **Maintenance script**
вставьте одну и ту же команду:

```sh
sh deploy/setup-codex-cloud.sh
```

Сценарий ставит зависимости приложения и инструменты разработки в виртуальное
окружение внутри контейнера Codex. Его путь не содержит данные приложения.
Сценарий не запускает тесты и не обращается к рабочему серверу. Если выбранная
ветка меняет зависимости, повторный запуск обновит их. Для полной проверки кода:

```sh
sh deploy/check-codex-cloud.sh
```

Эта команда запускает Ruff, mypy, pytest и сборку пакета. Сейчас она проверяет
код на подготовленных тестовых данных; она не поднимает YDB в Docker и не подтверждает
доступность внешних API. Для отдельного теста
используйте `$HOME/.cache/zont-analyzer-codex/venv/bin/pytest` с нужным путём.
Проверки выполняются в контейнере Codex Cloud; для локальной машины действует
[проверка через Docker](./container-development.md).

## Доступ к документации из задачи

В настройках **Agent internet access** выберите **On**, список доменов **None**
и добавьте только эти имена, без `https://` и путей:

| Домен | Для чего |
| --- | --- |
| `zont-online.ru` | [Описание методов ZONT API](https://zont-online.ru/api/docs/) |
| `developers.openai.com` | [Документация OpenAI API](https://developers.openai.com/api/docs/) |
| `learn.chatgpt.com` | Страницы Codex, на которые перенаправляет документация OpenAI |

Для чтения страниц достаточно разрешить методы **GET**, **HEAD** и **OPTIONS**.
Доступ к интернету в фазе подготовки остаётся доступным для установки
зависимостей. Список ограничивает сетевые команды во время работы агента.
Codex Cloud разрешает домены целиком, а не отдельные пути. Если нужен сервер
[OpenAI Docs MCP](https://developers.openai.com/learn/docs-mcp), он находится по
адресу `https://developers.openai.com/mcp`; для его протокола может понадобиться
POST. Обычные страницы документации доступны без него.

`my.zont.online` — адрес действующего ZONT API. Его методы, включая чтение,
обычно используют POST. Добавляйте этот домен и POST только для отдельной
задачи, которой действительно нужен прямой вызов API, с ограниченными
полномочиями и сроком действия токена. `api.openai.com` нужен для реальных
вызовов OpenAI API, но не для чтения документации. Разрешённый домен и метод
сами по себе не ограничивают действия внутри API; в обычной схеме реальные
проверки выполняются в dev-окружении после развёртывания.

Для реального вызова из контейнера Codex нужны и сеть, и ключ в фазе работы
агента. Обычные переменные окружения доступны агенту; поле **Secrets** доступно
только сценарию подготовки и удаляется перед работой агента. Поэтому секрет в
этом поле сам по себе не позволит выполнить интеграционный тест. Не записывайте
ключ в репозиторий или вывод команд. [Доступ и секреты в Codex Cloud](https://developers.openai.com/codex/cloud/environments#environment-variables-and-secrets).

## Как проверять работу с внешними сервисами

1. В Codex Cloud разработать изменение и выполнить проверки на подготовленных
   тестовых данных.
2. Локально или в GitHub Actions выполнить проверки внутри Docker, включая
   YDB в М3, затем собрать и проверить облачный образ. Push ветки `stageM<N>/...`
   с изменениями приложения запускает выпуск кандидата; открытие PR само по
   себе образ не публикует.
3. Развернуть выбранный проверенный образ по неизменяемому идентификатору его
   содержимого (digest) в изолированное окружение Yandex через защищённый
   сценарий GitHub Actions. Он получает доступ через GitHub Environment и
   кратковременное подтверждение личности (OIDC), а приложение получает ключи
   ZONT/OpenAI из Lockbox. Обычное
   развёртывание выполняет только короткий smoke готовности и синтетического
   расчёта. Реальные read-only проверки ZONT и ограниченный запрос OpenAI
   запускаются отдельно из развёрнутого контейнера. Лимит — не более одного
   реального запроса OpenAI на пользовательскую итерацию.
4. Для М3 отдельно проверить обязательные операции на управляемой YDB в
   проектном окружении. Пока эта проверка не автоматизирована в Codex Cloud;
   локальный тест на YDB в Docker не заменяет её.

Доступы к реальным сервисам остаются в защищённой конфигурации dev-окружения.
Рабочие данные и токены production не нужны для обычной облачной задачи.

Сценарий должен присутствовать в ветке, которую Codex использует для создания
контейнера. При использовании сохранённого контейнера Codex сначала готовит его
из основной ветки, затем переключается на ветку задачи и выполняет maintenance
script. Поэтому эти файлы нужно включить в `main` до первого запуска задач из
других веток. После изменения setup/maintenance script Codex сбрасывает кеш
окружения автоматически.

Codex Cloud подходит для подготовки изменений и проверок на фикстурах. Выпуск
образа и приёмка с реальными данными продолжаются по
[процедуре выпуска](./release-process.md): локальная сборка и проверки, затем
ограниченный smoke после развёртывания готового образа.
