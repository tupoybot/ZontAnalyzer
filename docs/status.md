## Дальнейший облачный план

- До первого облачного изменения приложения точный commit и digest работающего
  production закрепляются в защищённой ветке `old-stable` и неизменяемом теге.
  Исправления старого production идут короткими ветками и PR в `old-stable`.
  После приёмки М1 каркас отдельным PR включается в `main`; следующие облачные
  этапы идут короткими ветками от него. Образы из `main` старый production не обновляют.
- М2 — запуск и API; М3 — хранение YDB; М4 — импорт данных и полный цикл отчёта;
  М5 — защищённый web; М6 — эксплуатация; М8 — переключение и завершение перехода.
  М7 остаётся необязательным. Аналитика, пользовательские данные и проверки
  восстановления сохраняются; одинаковый образ для старой и новой систем не требуется.
- Каждый этап М2–М8 заканчивается инвентаризацией Yandex Cloud и удалением временных,
  заменённых и неиспользуемых сущностей с подтверждением через API провайдера.
  Для каждого сохранённого платного ресурса требуется действующий потребитель или
  проверенное назначение для восстановления; без этих доказательств этап не принимается.
- Это изменение плана, не реализация М2 и не приёмка М1.
  [Подробный порядок и критерии](./cloud_first_milestone.md).
