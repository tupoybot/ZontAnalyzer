# Инкрементальная публикация

Доработка этапа 9, 13 сентября 2026. Healthcheck и его настройки не меняются.

## Причина и поведение

Раньше каждый штатный цикл перечитывал весь архив, обновлял газовый контекст
и рендерил все отчёты, даже при отсутствии новых данных. На изолированной копии
149 опубликованных отчётов полный проход занимал около 15 секунд под профилировщиком;
на общем HK эта работа занимала существенно больше времени.

Теперь изменения исходных данных записываются в `publication_changes` в той же
транзакции. Повторные изменения одного ключа объединяются, ревизия растёт.
Публикация читает только новые ревизии и обрабатывает не более **8 отчётов за вызов**.
Последний дневной отчёт получает приоритет; остальная очередь сохраняет порядок
ожидания и переживает перезапуск. Изменение общих входов ставит затронутый архив
в очередь, а не запускает его полный пересчёт в одном цикле.

| Изменение | Обновление |
| --- | --- |
| Каноническая версия отчёта | Этот отчёт, газовый контекст и HTML |
| Комментарий или статус рекомендации | HTML отчёта; прямой feedback остаётся адресным |
| Применённое вмешательство/эксперимент | Зависимый газовый контекст и отображение |
| Реально изменённые данные часа UTC | Пересекающиеся периоды, сравнения и окна экономии |
| Поздняя телеметрия внутри калибровки газа | Газовый контекст архива, ограниченными пакетами |
| Показание/граница счётчика, профиль, семантика датчиков | Газовый контекст архива, ограниченными пакетами |
| Тариф | Стоимость пересекающихся окон; объём и модель газа сохраняются |
| Настройки/состояние обслуживания AI | HTML, без нового запроса AI |

Одинаковые повторные измерения, служебные даты обновления и меняющееся сырое
состояние устройства сами по себе не запускают публикацию архива. Активация
профиля с будущей датой и изменение часового пояса проверяются отдельно.
Прежние AI-выводы, время генерации, рекомендации и решения владельца сохраняются.

## Индекс, ошибки и восстановление

В каталоге публикации находится служебный `.publication-cache.sqlite3`. Это
восстанавливаемый индекс: метаданные архива, зависимости, очередь и обработанная
ревизия. Он независим для каждого каталога публикации. Исходная БД и сохранённые
JSON остаются источниками данных; файл индекса не должен раздаваться HTTP.

Писатели используют прежний `.publication.lock`. Файлы заменяются атомарно,
затем обновляется manifest, последним — latest. Ревизия подтверждается после
записи артефактов. Сбой может повторить работу, но не потерять её. Изменения,
поступившие во время публикации, остаются для следующего цикла.

Обычный пустой цикл не обходит архив и не переписывает HTML/JSON/manifest/latest.
Он проверяет служебное состояние и не более 16 пар файлов. Удалённый или внешне
изменённый файл восстанавливается при очередной проверке; это не немедленный
аудит всего архива. Добавленные экспорты обнаруживаются по изменению каталога.
Сохраняются валидные архивные файлы без соответствующей строки в БД.

При потере/несовместимости индекса выполняется однократная индексация: читаются
метаданные и по одному отчёту, без загрузки всех полных отчётов в память.
Дальнейший пересчёт снова ограничен пакетами. При ручном пересоздании одного
отчёта публикация и снимок для отката затрагивают только его артефакты, manifest
и latest, а не содержимое всего архива.

`report publish` обрабатывает один пакет и возвращает `rendered_reports` и
`pending_reports`; обычный worker продолжает очередь в следующих циклах.
`report publish --rebuild` заново индексирует архив и ставит его в очередь.
`--batch-size N` допускает 1–100 отчётов. Большие архивные прогоны и восстановление
проверяются локально; для штатного HK остаётся размер 8.

Рост архива всё ещё увеличивает размер manifest и стоимость восстановления
индекса. Обновление manifest читает компактные метаданные, когда публикация
действительно изменилась. Газовая модель сохраняет исторические зависимости;
изменение старого показания может законно затронуть много отчётов. Ограничивается
работа за цикл, а не полнота такого обновления.

## Миграция и проверка выпуска

Миграция `d92a10b4c601` → `f1a2b3c4d5e6` добавляет только журнал и триггеры.
Она не переписывает телеметрию, отчёты или данные владельца. Для отката приложения
сначала выполнить downgrade этой миграции после остановки worker: прежний образ
не знает новую Alembic-ревизию. Удаление журнала/индекса не удаляет исходные данные;
повторное обновление начнётся с восстановления индекса.

Локальные проверки включают пустой цикл, ограниченный пакет, перезапуск очереди,
изменение во время публикации, позднюю телеметрию/калибровку, тарифы, восстановление
индекса и файлов, откат ручного пересоздания. Полный набор и окончательные
измерения фиксируются в статусе выпуска после проверки финального образа.

Промежуточная локальная проверка исходников в Docker: **667 тестов**, Ruff и mypy
прошли. Синтетический архив **1095 отчётов** (три года дневных публикаций):
пустой цикл 11–12 мс при 1 CPU/384 МБ, без рендеринга. Это проверка роста архива,
