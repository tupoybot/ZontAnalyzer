# Журнал ручных экспериментов

`#for-human`

В отчёте действие «Начать эксперимент / Зафиксировать изменение» доступно даже
без рекомендаций. Приложение записывает сообщение владельца и читает данные
ZONT; настройки контроллера оно не меняет.

В одной записи можно указать несколько параметров, их значения до и после,
устройство и известный контур. Список устройств и контуров определяет сервер
по сохранённым данным отчёта и устройства. Произвольные идентификаторы и
рекомендации другого отчёта отклоняются.

План и выполненное изменение — разные состояния. Для выполненного действия
можно указать время либо оставить его неизвестным. Часовой пояс берётся из
отчёта, независимо от пояса браузера. Время сохранения показывается отдельно
и не заменяет время действия. Цель, ожидаемый эффект, срок наблюдения и
комментарий сохраняются вместе с параметрами.

Запись можно уточнить, завершить, досрочно остановить или отменить до выполнения.
Откат сначала можно запланировать, затем отметить выполненным. Эти отметки
описывают слова владельца; ни план отката, ни сообщение о выполнении не означают
подтверждения телеметрией. Для выполненного отката можно указать отдельное время.
Отметка выполненного отката означает возврат всех перечисленных параметров
к значениям «до»; в истории сравнения направление значений меняется на обратное.
Исходные цель, ожидание и прогноз отчёта сохраняются неизменными, последующие
правки добавляются в историю. Завершённую или отменённую запись нельзя превратить
обратно в новый план.

Журнал использует защищённый API отчёта: `GET` и `PUT /api/reports/{id}/experiments`.
`request_id` позволяет безопасно повторить запрос после потери ответа;
`expected_revision` защищает от перезаписи чужой более свежей правки. При ошибке
форма сохраняет введённые поля. Успешное сохранение и повторное открытие журнала
не требуют нового запроса к ИИ.

Для сравнения периодов используется общая история ручных действий, включающая
прежние записи по рекомендациям. Новые планы не становятся фактической границей
сравнения. Выполненное действие с неизвестным временем передаётся отдельно как
неопределённое вмешательство: оно может ограничить вывод по соответствующему
устройству и контуру, но не получает выдуманную дату. Известное
время изменения и выполненного отката передаются в общую историю отдельно,
с указанием сообщения владельца как источника. [Автоматическое сопоставление](./regulation-comparison.md)
с наблюдаемой историей настроек сохраняет различие между этими источниками.
Если одна и та же связанная с рекомендацией запись есть и в прежней истории,
и в журнале, совпадение времени, устройства, контура, параметров и значений
считается одним действием. Разные действия по одной рекомендации сохраняются
отдельно; при неизвестной области применения совпадение не предполагается.

Журнал с полной историей хранится в дополнительной таблице `owner_experiments`.
Для сравнений отдельная таблица `owner_experiment_events` содержит проекции
исходного изменения и выполненного отката. Известное время и неизвестное время
хранятся раздельно; служебный ключ неизвестного времени используется только
для индексного чтения и никогда не показывается как дата действия. Изменение
журнала и этих проекций выполняется одной транзакцией. Уточнение времени заменяет
нужную проекцию, сохраняя историю журнала и исходный прогноз.

Чтение для сравнений идёт по индексу времени действия, от новых записей к старым,
с ограничением числа событий и отсечкой по времени до этого ограничения. Поэтому
запрос за период до отката видит исходное изменение. Общая история получает
не более двух запрошенных объёмов новых событий, максимум 1000 за вызов, затем
убирает точные повторы и возвращает запрошенное число записей. Полный журнал
при этом не перечитывается; ограничение выборки не удаляет старые события.
Выполненные действия с неизвестным временем читаются отдельным ограниченным
запросом по индексу. Переполнение любой выборки явно ограничивает достоверность
сравнения. Изменённое выполненное действие ставит затронутые отчёты в очередь
обновления фактов; одинаковый повтор не создаёт новую работу и не вызывает ИИ.

Для уже существующих записей утилита
[`backfill_owner_experiment_events.py`](../../tools/backfill_owner_experiment_events.py)
проверяет не более 100 журналов за порцию. По умолчанию она только показывает
число расхождений; запись требует `--apply`. Продолжение сохраняется в приватный
файл вне репозитория. Исправление заново читает текущий журнал внутри транзакции,
обновляет только его проекции и уведомление об изменении. Сам журнал, история
уточнений и прогноз не меняются; повтор исправленной порции ничего не записывает.

Базовый контракт таблиц YDB и прежняя история рекомендаций не меняются. При
резервном копировании нужно включать обе дополнительные таблицы; старые версии
приложения их не удаляют.

Проверка: открыть отчёт без рекомендаций, записать два параметра, повторно
открыть журнал, завершить наблюдение и отметить план/выполнение отката. Проверить,
что исходная цель осталась в истории, время соответствует поясу отчёта, а ошибка
сохранения не очищает форму. Автоматические проверки находятся в
[API-тесте](../../tests/integration/test_owner_experiments.py) и
[браузерном сценарии](../../tests/integration/owner_experiments_browser.mjs).
