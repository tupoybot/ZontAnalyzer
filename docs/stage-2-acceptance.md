# Этап 2 — временные свидетельства отопления и ГВС

Ветка: `stage2`, от актуального `origin/main`. Приёмка выполняется 2026-09-06.
**Статус: реализация и локальная приёмка; этап пока не закрыт.**

## Контракт

- `analytics/evidence.py` формирует отдельный типизированный пакет в
  `Report.context.temporal_evidence`. Схема SQLite и схема ответа AI не меняются.
- Источники обозначены устойчивой комбинацией device/source/entity/metric, названием
  из ZONT, единицей и происхождением. Неоднозначный выбор ряда остаётся unknown.
  Для ΔT используется явно выбранная либо однозначная внешняя обратка; неподтверждённый
  `rwt` адаптера не подставляется вместо внешнего измерения.
- Контрольная комната сопоставляется с историческим заданием контура. Текущее ручное
  предпочтение температуры не переписывает историческое задание в пакете свидетельств.
- Окна сохраняют точные границы UTC, часовой пояс дома, ID, значения и диапазоны,
  изменения и независимое покрытие каждого ряда. Длинный период использует тот же
  ограниченный размер пакета; пропущенная информация отмечается явно.
- Состояние горелки определяется `fl`. Нулевая модуляция при `fl=1` остаётся
  наблюдаемой точкой шкалы активного горения. Профиль
  `analysis.modulation_capability_profile: flame_zero_is_minimum` выбирается только
  при подтверждённой семантике оборудования; default — `unknown`. Пересчёта в кВт нет.
- KPI имеют знаменатель, покрытие и причину недоступности. Приоритет ГВС, летний/выключенный
  режим, переходы задания/режима, ненадёжные интервалы и ранее отфильтрованный шум
  исключаются из сопоставимых расчётов отопления.
- Погодные ступени характеризуются по исходным отсчётам; это не измерение причины
  изменения погоды. Совпадающие изменения температуры комнаты/ГВС и скорость остывания
  доступны в одних временных окнах. Без прямого сигнала рециркуляции работа насоса и
  присутствие людей не объявляются измеренными фактами.
- AI получает пакет в существующем входном контракте. Полный compact JSON ограничен
  64 KiB, исключённые объекты учитываются в `provenance.truncation`. Прежняя схема
  ответа сохранена; ID окон можно указывать в `evidence_event_ids`.
- В HTML/text есть раскрываемые временные свидетельства с именами показателей,
  местными интервалами и пробелами. Старые отчёты без этого контекста совместимы.
  Встроенные графики для этапа не требуются.
