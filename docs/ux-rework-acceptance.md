# UX rework — специальный этап вне плана

Ветка `ux-rework`; merge запрещён до отдельного решения владельца.
Этапы аналитического плана не продвигаются.

## Изменения

Общий standalone HTML для daily/weekly/monthly: компактная навигация, закрытый
архив, состояние и шесть KPI, главный совет рядом с температурным графиком,
единая тепловая система CH/ГВС с инженерным графиком, значимые события,
остальные рекомендации и сгруппированные подробности. На узком экране колонки
складываются; инженерный график доступен в Debug.

Debug по умолчанию выключен, сохраняется в localStorage; `?debug=1` включает
технический слой в контексте метрики, события, рекомендации и источника.
Полный canonical JSON, временные и исторические свидетельства сохранены.
Нормальное состояние не выводится только из отсутствия событий: утверждение
«Система работает штатно» требует соответствующего заключения самого отчёта.

Профиль закрыт и открывается из header. Показание газа и редактор разделены,
история доступна отдельно. Комментарий рекомендации раскрывается по запросу;
редактирование сохранённого комментария сохраняет applied/rejected. Для новой
рекомендации комментарий сохраняется вместе с выбранным решением, как требует
существующий API. Существующие заметки, reset-to-auto и аудит не меняются.

SVG строится из реальных выбранных рядов, не из почасовых средних. Темы сигналов,
пунктир целей, единицы, временные оси и легенды общие для всех периодов. Пропуски
не соединяются после прореживания; выборка сохраняет настоящие экстремумы и
границы разрывов. Полосы показывают подтверждённое телеметрией пламя CH/ГВС,
не приписывая этому сигналу семантику запроса отопления.

DTO, canonical report JSON, расчёты, OpenAI-контракт, feedback/owner API и БД
не меняются. При публикации HTML выполняется отдельное чтение телеметрии.
Кэш `/data/chart-data-cache` (в общем случае рядом с SQLite) вне публичного архива
атомарен, проверяет версию схемы и хеш canonical report. На один report ID хранится
один файл: регулярный пересчёт дня не накапливает старые варианты кэша. Повторная публикация
не перечитывает архивную телеметрию. Историческое исправление телеметрии отражается
после пересчёта соответствующего отчёта; ошибка кэша не блокирует публикацию.
Кэш подготавливается локально и доставляется вместе с HTML, чтобы не прогревать
архив на HK.
