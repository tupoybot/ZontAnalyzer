# ZontAnalyzer: что требуется от владельца

Обновлено: 2026-08-03. Команды первого запуска находятся в [README](../README.md), порядок
разработки — в [roadmap](./roadmap.md).

Принцип: владелец не переписывает сведения, которые приложение может надёжно получить из ZONT.
Оборудование, датчики, режимы, расписания и уставки сначала определяются read-only discovery.

## Для локального пилота

Нужно только:

1. предоставить существующий ZONT token и контактный e-mail через private-файл или environment;
2. проверить результат `doctor --live` и inventory команды `discover`;
3. открыть первый локальный HTML-отчёт и отметить непонятные или неверные выводы;
4. не менять настройки котла только ради теста анализатора.

Секреты нельзя присылать в чат или сохранять в Markdown. Локальные файлы
`.access/zontaccesstoken.json` и `.access/.openai_access_token.txt` исключены из Git и должны
иметь права `0600`.

Ручной `config.yaml` не обязателен. [config.example.yaml](../config.example.yaml) нужен только
для точечных overrides, когда discovery ошибся или владелец осознанно меняет preference.

## Что полезно подтвердить во время пилота

Приложение вправе попросить подтверждение только если от него действительно меняется вывод.
Наиболее полезны ответы:

- правильно ли сопоставлены отопительный контур, комнатный датчик и БКН;
- был ли замеченный переход режима ручным;
- был ли в конкретном эпизоде реальный запрос тепла от тёплых полов;
- совпала ли найденная пауза после ГВС с наблюдаемым поведением дома;
- было ли резкое падение температуры БКН обычным водоразбором;
- понятен ли отчёт и какое наблюдение оказалось полезным или ложным.

Модель котла, timezone, список датчиков и режимы не нужно повторять, если ZONT уже вернул их с
высокой уверенностью.

## OpenAI — только после локального отчёта

Если владелец хочет AI-интерпретацию:

1. создать отдельный OpenAI project с небольшим budget/alerts;
2. сохранить project API key в password manager;
3. передать его как `OPENAI_API_KEY` или private-файл, но не в Git/YAML/image;
4. явно включить `openai.enabled: true` и сначала выполнить один контролируемый анализ.

OpenAI получает компактные рассчитанные факты, а не сырую телеметрию. Приложение продолжает
собирать данные и строить локальные отчёты без AI.

## Telegram пока не требуется

Telegram provider и pairing-команды ещё не реализованы. Создавать бота и token сейчас не нужно.
К каналу доставки вернёмся только после того, как ежедневный HTML/лог подтвердит пользу.

## Перед production deployment

После успешного локального пилота владельцу потребуется выбрать:

- сервер и способ запуска;
- постоянный каталог/volume данных;
- место внешнего backup вне основного диска/volume;
- способ одноразового provisioning runtime secrets;
- нужен ли Telegram или простой read-only UI.

GitHub Actions или deploy-процесс не должны перезаписывать БД, пользовательский config и secrets.
Приложение остаётся read-only относительно ZONT на всех этапах.
